# 地域課題マップ・市町村カルテシステム

大阪府 市町村局振興課 内部職員向けの、地域課題マップ・住民目線マップ・市町村カルテ・分析レポートを提供するツールです。
`app.html` を直接ブラウザで開くだけで、そのまま動作します（サーバー・ログイン不要）。

**スコープ**：地域課題マップ（行政の計画視点、8指標）／住民目線マップ（住民の生活視点、4指標）／市町村カルテ／分析レポートの4機能。
相談・訪問履歴管理、ダッシュボード、アンケート結果分析、認証・バックエンド接続は対象外です。

---

## 1. システム構成

```
┌──────────────────────────────────────────────────────────┐
│                     ブラウザ（PC・タブレット）                │
│  app.html（単体ファイル・サーバー不要）                       │
│   ├─ 市町村統計データ：e-Stat・総務省・大阪府の実データを埋め込み │
│   ├─ 市町村境界GeoJSON：国土数値情報(N03)由来のデータを埋め込み  │
│   ├─ 課題スコア：統計データから決定的に算出（JS内ロジック）      │
│   └─ 分析レポート：ルールベースのローカル生成（外部API呼び出し無し） │
└───────────────────────────────┬────────────────────────────┘
                                 │ HTTPS（タイル画像の取得のみ）
┌───────────────────────────────▼────────────────────────────┐
│  外部サービス：国土地理院 地理院タイル（地図背景画像の配信のみ）  │
└──────────────────────────────────────────────────────────┘
```

**ポイント**
- サーバー・データベース・ログインは無し。認証やアクセス制御が必要になった時点で、ホスティング先
  （社内ファイルサーバー、簡易な社内Webサーバー等）側のアクセス制限で対応する想定。
- 地図の背景は**国土地理院の地理院タイル「淡色地図」**（`https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png`）をLeafletで表示する。標準地図（等高線・道路網が密）は着色データと競合して見づらいため、データ可視化用に作られた淡色地図を採用している。利用は無償・APIキー不要だが、地理院タイルの利用規約に従い「地図：国土地理院」の出典表示を行う。
- 市町村は**コロプレス（境界ポリゴンの塗り分け）**で表示する。境界データは国土数値情報「行政区域データ（N03）」を基にしたGeoJSON（大阪市・堺市は区データを結合）を使用し、選択した指標のスコアで塗り分ける。円マーカーではなく実際の行政区域ポリゴンなので、都市部で市町村が重なって見えなくなる問題が発生しない。
- 地図の表示・パン可能範囲は、このポリゴンの外形（`getBounds()`）にフィットさせて固定する。これにより初期表示・パン・ズームのいずれでも近隣府県が大きく映り込まず、大阪府内に視点が留まる。
- 市町村統計は複数の公的統計の実データ（人口・高齢化率・世帯数・財政力指数等はe-Stat「社会・人口統計体系」、空き家率は総務省統計局「住宅・土地統計調査」、マイナンバーカード保有率は総務省、土砂災害警戒区域数は大阪府）。課題スコア（8指標）はそこから決定的に算出する（`computeScores`関数）。詳細はアプリ内「指標の計算方法」画面を参照。
- 住民目線マップの4指標はすべて実データ。「買い物の不便さ」は農林水産省「食料品アクセスマップ」（2020年）、「医療への行きにくさ」「学校への通いにくさ」は可住地面積当たりの施設密度としてe-Stat「社会・人口統計体系」から算出。残り1指標「地元で買えない度」（支出流出入率）と、市町村カルテの「将来人口（2050年推計）」「業種別事業所数」は、RESAS（地域経済分析システム）のAPIが2025年3月に提供終了しているため、RESASの新サイト（resas.go.jp）の「地域ビジネス環境分析」を市区町村ごとに開いて取得した実データ。
- 分析レポートは外部APIを呼ばず、地域課題マップ8指標・住民目線マップ4指標のスコアから共通課題・特徴的な課題・住民目線で見た課題・支援方針・広域連携の可能性をルールベースで生成する。ブラウザへの保存（localStorage等）は一切行わない、完全な表示専用ツール。

## 4. データ構造

サーバー・DBを持たないため、`app.html`内のJavaScriptオブジェクトがそのままデータモデルです。

### 4.1 市町村マスタ（`RAW` → `MUNIS`）
| 項目 | 説明 |
|---|---|
| id | 短縮ID（例: `osaka`） |
| name | 市町村名 |
| region | 地域ブロック（北大阪／北河内／中河内／南河内／泉北／泉南／大阪市域） |
| lat, lng | 代表座標（ポップアップ位置の目安。地図の塗り分け自体はGeoJSON境界を使用） |
| population | 人口（2020年国勢調査） |
| popChangeRate | 人口増減率%（2015→2020年の年率換算） |
| agingRate | 高齢化率%（65歳以上人口／総人口） |
| areaKm2 | 面積km2 |
| households | 世帯数 |
| fiscalIndex | 財政力指数（総務省、直近公表年度） |
| vacantRate | 空き家率%（住宅・土地統計調査。小規模5町村は`null`） |
| aloneElderlyRate | 65歳以上単独世帯率%（国勢調査） |
| elderlyWorkerRate | 高齢就業者割合%（65歳以上、国勢調査） |
| cardRate | マイナンバーカード保有率%（総務省、令和8年8月末） |
| hazardCount | 土砂災害警戒区域数（大阪府指定） |

### 4.2 課題スコア（`computeScores(m)`が返す8指標、1〜5）
`population / aging / vacant / transit / community / successor / disaster / dx` の各キーで、
上記の実データから決定的に算出する（計算式はアプリ内「指標の計算方法」画面参照）。「公共交通」のみ、
全市町村共通の公的統計が見つからなかったため人口密度からの推定値。`vacant`は`vacantRate`が`null`の
5町村（能勢町・田尻町・岬町・太子町・千早赤阪村）では`null`となり、地図はグレー表示、`m.composite`
（総合スコア）の算出からも除外される（推定値による代用はしていない）。

### 4.3 住民目線データ（`RESIDENT_RAW` → `MUNIS`の各プロパティ）
「人口当たりの施設数」で測ると、人口が減った町村ほど見かけ上「1人当たりの施設が多い＝恵まれている」と
出てしまい住民の実感と逆になる（例：千早赤阪村は人口4,909人・診療所5軒で「人口10万人当たり102施設」と
府内最上位になるが、実際には村内の移動距離が長い）。そのため住民目線マップの指標は「供給量」ではなく
**行きにくさ（距離・密度）**で測る形に組み直している。人口を母数から外し、可住地面積当たりの施設密度と、
国が実測した買い物困難人口の割合を使う。

| 項目 | 説明 |
|---|---|
| foodAccessRate | 食料品アクセス困難人口割合%（65歳以上、農林水産省「食料品アクセスマップ」2020年）。店舗まで直線500m以上かつ自動車利用が困難な高齢者の割合。 |
| clinicDensity | 一般診療所数（可住地面積100km²当たり、2023年度） |
| schoolDensity | 小学校＋義務教育学校数（可住地面積100km²当たり、2024年度、学校基本調査） |
| habitableKm2 | 可住地面積km²（総面積から林野・湖沼を除いた面積） |
| leakageRate | 支出流出入率%（RESAS「地域ビジネス環境分析」、2022年。非公開の2市は`null`） |

`residentScores`（`food / clinic / school / leakage`、1〜5）と`residentComposite`（単純平均）も
`MUNIS`の各要素に持たせている。`food`のみ値が大きいほど課題が大きい（`residentScaleScoreUp`）、
残り3指標は値が悪い（施設密度が低い・支出が域外へ流出）ほどスコアが高くなるよう反転している
（`residentScaleScore`）。

施設密度の2指標（`clinic / school`）は、市街地と山間部で100倍以上開くため**常用対数（log10）**に変換して
から点数化する。また可住地面積が小さい市町村では施設1件の増減で密度が大きく振れるため、可住地面積を
母数とした**小規模自治体補正**（`shrinkDensity`関数、信頼度加重平均＝縮小推定）をスコア化の前にかけ、
`m.clinicDensityAdj / m.schoolDensityAdj`として保持する。経済指標である`leakageRate`はこの補正の対象外
（計算式は「指標の計算方法」画面参照）。

`NURSING_PER1K` → `m.nursingPer1k`（介護施設定員／65歳以上人口千人）は、広域から利用者を受け入れる大規模
施設が小規模町村に1つあるだけで数値が跳ね上がり「その町の住民が受けやすい」ことを意味しないため、
スコア化せず市町村カルテの参考値としてのみ表示する。図書館数も大阪市・堺市以外ほぼ全市町村で0〜3館しか
なく市町村間の比較に耐えないため、指標から外している。

### 4.4 RESASデータ（`RESAS_POP2050` / `RESAS_LEAKAGE` / `RESAS_INDUSTRY`）
RESASのAPIは2025年3月に提供終了しているため、RESASの新サイト（resas.go.jp）の「地域ビジネス環境分析」を
市区町村ごとに開いて取得した実データ。`RESAS_LEAKAGE`は上記`leakageRate`の元データ。

| 項目 | 説明 |
|---|---|
| `RESAS_POP2050` → `m.pop2050` / `m.popRate2050` | 2050年推計人口（人）、2020→2050年増減率%。市町村カルテの基本指標に参考表示（スコア化なし）。 |
| `RESAS_INDUSTRY` → `m.industry` | 生活関連12業種の事業所数`[2016年,2021年]`の配列（`INDUSTRY_LABELS`と対応）。事業所数1〜2件の業種はRESAS側の秘匿処理で`null`。全業種が非公開の市町村（交野市）は配列全体が`null`。市町村カルテに参考表示（スコア化なし）。 |

### 4.5 市町村境界（`OSAKA_GEOJSON`）
GeoJSON `FeatureCollection`。各Featureの`properties.id`が4.1の`id`と対応する。大阪府43市町村分。地域課題マップ・
住民目線マップの両方で共有する。

## 6. 今後の拡張余地

複数職員での共有・編集や、認証が必要になった場合は、以下のような追加が考えられます（現状は未実装）。

- **担当者メモ・引継ぎ記録**：市町村ごとのメモを職員間で共有したい場合は、簡易なバックエンド（Supabase等）を保存先として追加する。ブラウザの`localStorage`は端末をまたいで共有されないため、単体ファイルのまま実装する選択肢は取らない。
- **アクセス制御**：社内ネットワーク限定公開、または簡易なBasic認証をホスティング側で設定する。
- **分析レポートの高度化**：`computeScores`と同じ入力データを使い、OpenAI等のLLM APIを呼ぶサーバー側の中継エンドポイントを追加する（APIキーをブラウザに置かないため）。
- **相談・訪問履歴管理・アンケート分析・ダッシュボード**：今回のスコープ外だが、同じ市町村マスタ・スコアを土台に追加可能。

## 7. 実装コード一式

`app.html`をブラウザで直接開くと、地域課題マップ／住民目線マップ（どちらも国土地理院地図＋Leafletのコロプレス、大阪府内に表示範囲固定）／市町村カルテ／分析レポート（ルールベース生成）が一通り動作します。

- 地図は実際に国土地理院の地理院タイル（淡色地図）を読み込みます。市町村は実際の行政区域境界ポリゴン（国土数値情報N03由来）で塗り分けます。表示・パン範囲はそのポリゴン外形にフィットさせて大阪府内に固定しているため、近隣府県が大きく画面を占めません。市町村をクリックするとポップアップから市町村カルテに遷移します。
- 統計データは複数の公的統計の実データ（大阪府43市町村の人口・高齢化率・世帯数・面積・財政力指数・空き家率・高齢就業者割合・マイナンバーカード保有率・土砂災害警戒区域数・食料品アクセス困難人口割合・可住地面積当たり診療所数／学校数・介護施設定員・支出流出入率）。指標ごとの算出方法はアプリ内「指標の計算方法」画面にまとめている。市町村カルテの「将来人口（2050年推計）」「業種別事業所数」はRESASサイトから取得した参考データ（スコア化なし）。

**注記**：Claude Artifactのプレビュー（claude.ai上のホスト環境）では、セキュリティ上の制約により地理院タイルサーバーへの画像リクエストがブロックされ、地図の背景タイルが表示されない場合があります。`app.html`をこのリポジトリからダウンロードして通常のブラウザで直接開けば、この制約は適用されず正しく表示されます。
